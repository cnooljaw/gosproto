# gosproto 性能优化设计与验证原则

P0～P5既定计划已完成，现状见[优化状态](GOSPROTO-OPTIMIZATION-STATUS.md)和[最终结果](benchmarks/SUMMARY.md)。本页保留长期适用的设计原则；原918行方案、逐轮实验日志及未采用候选完整保存在[档案](benchmarks/README.md)及[v1.0.0原文](https://github.com/cnooljaw/gosproto/blob/v1.0.0/docs/RFC-GOSPROTO-PERFORMANCE.md)。原始计时和判定未改写，本页不是新的性能证据或实施授权。

## 优化方向

| 方向 | 已采用的机制与必须保留的边界 |
| --- | --- |
| P0 字节操作 | 标准库LittleEndian、固定有界视图、编译器范围证明；完整输入检查保持 |
| P1 字段访问 | 绑定稳定类型事实，当前调用核对实际owner/类型/形状；公开元信息变化和命名类型保留回退 |
| P2 数值数组 | 按4/8字节宽度使用专用循环及受控批量访问；保留signed语义、窄化与unsigned超界检查 |
| P3 编码布局 | 调用内复用实际尺寸、头项数和数组宽度，双游标写出；不跨调用缓存业务对象或上次布局 |
| P4 解码构造 | 有界稠密索引与稀疏查询，受控字段/槽写入；临时根对象成功后提交，子对象及指针结果独占 |
| P5 Pack/Unpack | 分开测普通mask、FF、零段、尾部和256-word边界；原生入口限定类型与范围，保留purego/其他架构回退 |

EncodePacked及RPC使用调用内独占工作区，公开Encode/Pack结果保持独占；内部借用不扩展为调用方持有的共享视图。unsafe/汇编必须有明确私有入口、类型与范围证明；Go写屏障不能由字节复制指针替代。

## 证据与控制

1. wire以固定cloudwu/sproto官方实现和独立向量为准，不仅做自身往返；不模拟官方已知的错误符号扩展。
2. 先用profile定位热点，再隔离单一候选；profile与正式计时分开，不并发争抢CPU。
3. 固定实际源码、工具链、输入和二进制指纹。分别记录Encode/Decode、Pack/Unpack、分阶段组合与真实原生入口，不用手工组合冒充融合入口。
4. 保留原始轮次、绝对耗时、分配、控制失败、GC、长尾和反向。小而可信的收益可以保留，不设统一最低百分比，不扣除控制值，不从反复采样中挑最好结果。
5. 低分配不是唯一目标。对象数量、结果独占、presence、错误顺序、失败原子性、资源预算和buffer cap均为验收契约。
6. 结构/运行时不同的Go与TS只比较各自同场基线；历史跨日期数值用于趋势，不作单补丁归因或跨平台保证。

## 后续工作

活跃工程和命令见[Benchmark](../benchmarks/README.md)，新输出进入ignored `tmp/`。有业务热点时重新建立当前公开API基线，Body与Packing分别定位；不重复已否定方案而缺乏新证据。修改对象模型、公共API、生成器、资源预算或跨调用内存复用时先提出独立方案。当前没有因归档新增的优化承诺。

# gosproto Go 编码规范

从 GSR 的同名规范选择适用于独立协议库的规则；不沿用 Service、Mailbox、Runtime 生命周期等业务框架约束。

## 必须遵守

- 使用 gofmt；函数正常分行，不用分号压缩控制流；约120列只作可读性提示。
- 名称表达 wire、字段、范围、所有权或操作含义；统一 ID、RPC、URL 等缩写。方法接收者具名且同一类型一致，不用 this/self。
- 错误、无效输入和结束分支优先返回；不用 panic 表达预期坏包或预算不足。
- 用 errors.Is/As 及稳定错误判断；包装错误增加有用上下文并用 %w 保留错误链，不以文本分支。
- 使用方定义最小必要接口；普通编解码函数不为形式统一加接口或包装层。重要真实接口角色的断言紧跟类型定义。
- 依赖显式传入，构造建立不变量；不添加全局当前请求或连接，不用 context 作为依赖容器。
- 编解码同步完成，不自行启动 goroutine。共享元数据需要明确并发契约，不保存调用方消息指针或跨调用尺寸。
- 导出符号有契约价值的 Go doc；自然语言尽量中文。机器指令、构建约束和许可证保留原文。
- 每个 Test 函数前说明它保护的可观察行为；优先测试公开契约，必要的底层边界测试说明其增量。
- 不顺手重构无关代码，不新增未使用的框架能力，不为了缩短代码隐藏预检与失败顺序。

## 性能代码

- 优先标准库字节操作与明确循环；用 profile 和汇编检查确认成本，而不是凭经验堆技巧。
- unsafe 必须具备实际Go类型、字段owner、布局及当前描述匹配的证明；保留命名类型、描述变更等回退。
- Go指针写入保持类型化和写屏障；不靠字节复制写Go指针，不依赖 reflect.Value 私有布局。
- 汇编入口有界、同步、不保留源，覆盖尾部、FF边界、重叠工作区、只读源、保护页及跨架构回退。
- 失败不能部分污染目标；已返回结果不被后续调用覆盖；不通过删检查、放宽额度或共享输出提速。
- 公开API或wire变化与局部优化分开裁决。不要为了优化引入尚无真实需求的generator、池或公共配置。

## 验证层级

1. 局部修改：gofmt和最相关测试。
2. 完整库切片：go test ./... -timeout=2m，按风险补vet、purego及race/checkptr。
3. 跨语言或阶段验收：独立TS测试、Benchmark夹具校验、官方C/Lua对照及使用方集成。
4. 平台实现：生产跨架构编译，明确区分编译、测试编译与真实运行。

不要机械使用 -count=1 或清缓存；超时先定位，必要验证未运行必须明确报告。
